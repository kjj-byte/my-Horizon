### [爱沙尼亚 IVXV 在线投票系统源代码公开于 GitHub](https://github.com/valimised/ivxv) ⭐️ 8.0/10

Hacker News 用户提交了爱沙尼亚在线投票系统 IVXV 的 GitHub 源代码仓库（valimised/ivxv），使外界可以直接查看这套系统的实现。该条目只提供仓库链接，没有给出具体版本号、发布说明或部署范围，因此讨论集中在源代码能否证明投票安全、可验证和可信。对安全研究者、选举机构和开发者来说，可审计性是讨论的核心，但公开代码并不自动等于选举结果可验证。

hackernews · theanonymousone · 10月17日 03:18 · [社区讨论](https://news.ycombinator.com/item?id=50127586)

**「背景」** 爱沙尼亚自 2005 年起在全国选举中使用网络投票，现行系统代号为 IVXV。ACM 论文指出，IVXV 协议套件于 2017 年发布，并引入投票登记服务，使投票收集委员会无法在不被发现的情况下丢弃选票；IEEE 论文还提到，2024 年欧洲议会选举公布的源代码已包含增强的审计应用，用于核验计票与混合结果。

**「影响」** 实际影响是：研究者和公众可以检查 IVXV 的代码路径，但评论者强调，代码公开只是审计起点，仍需构建可复现性、固件与运行环境验证，以及投票结束后的统计抽检，才能支撑对结果的信任；缺少这些环节时，源代码公开本身不足以说明投票机器是否按预期运行。

**「社区讨论」** 爱沙尼亚本地评论者表示，电子投票自 2001 年起使用、2007 年首次用于议会选举，源代码公开在 IT 圈内早已为人所知并受到重视。另一部分评论者则担心，软件即使结合硬件也无法单独保证选举安全，并指出一旦公众信任流失，纸质计票或数字计票都会面临合法性问题。

### [OpenCode 旧系统遭入侵，1.4% 用户 API 密钥或外泄](https://www.ithome.com/1/014/434.htm) ⭐️ 7.0/10

OpenCode 披露，当地时间 10 月 16 日发生安全事件：有人未经授权访问了其一个正处于停用流程中的旧系统，导致 1.4% 的 OpenCode Console 用户工作区中保存的第三方 API 密钥（如 OpenAI、Anthropic 密钥）可能外泄。公司称已于 10 月 17 日上午通过邮件通知所有受影响用户，未收到邮件者不受影响，并表示正与 Anthropic、OpenAI 和谷歌合作处置，但因事件仍在处理未披露更多细节。多名用户在讨论中报告了异常扣费，例如 Anthropic 账户约 400 美元、谷歌服务约 200 欧元，并称在收到 OpenCode 通知前先收到服务商的使用提醒；这些金额来自用户自述，尚非厂商确认的损失统计。

rss · IT HOME · 10月18日 00:19

**「背景概念」** OpenCode Console 允许用户把 OpenAI、Anthropic、Google 等第三方服务商的 API 密钥保存在自己的工作区中，供该工具调用模型；这类密钥本身就是可直接使用的凭据，任何人拿到后都能以密钥所有者的名义发起请求，并让密钥所有者承担相应费用。OpenCode 将此次事件称为“蒸馏攻击”，即攻击者利用窃得的凭据批量调用模型，再把模型输出用于训练其他模型或转售。

**「受影响用户需轮换密钥并核查账单」** 对收到通知的 1.4% Console 用户而言，工作区中存储的 OpenAI、Anthropic 等 API 密钥可能已被用于以账户持有人名义发起请求，从而产生费用；已有用户报告 Anthropic 约 400 美元、Google 约 200 欧元的未经授权支出。OpenCode 表示已通过邮件通知所有受影响用户，但相关密钥仍应立即在对应服务商处吊销或轮换，并核对用量与账单，而不能只等平台后续说明。

### [当写作不再是工作量证明](https://seangoedecke.com/writing-is-no-longer-proof-of-work/) ⭐️ 6.0/10

rss · Sean Goedecke · 10月18日 00:00

**「背景」** Sean Goedecke 认为，科技公司结构性依赖写作充当证据，而不只是沟通；这种写作可类比比特币的工作量证明。LLM 的出现正在瓦解这套证据机制。

**「方案」** 作者把职场写作分为三类：合规证据（如风险模板，实为满足法律或流程、震慑轻率改动）、努力证据（顾问的百页报告、个人项目的工单，内容之外更证明投入）和学习证据（层层汇总的状态报告迫使管理者建立基本理解）。这些文本的内容常不是重点，组织看重的是“确实坐下来写了”；这套机制依赖信任，公司只能靠事后或主动抽查防伪，而区块链则可自动校验哈希。但 LLM 能按需生成任意长文，作者称 2023 年后合规、努力、学习三类证据同时失效，学校与监管机构也受波及。他把现状称为“悬置期”：流程还在，人人却知道可轻易利用；视频或现场汇报、禁用 AI 写作、让 LLM 审查代码等替代方案，要么增加阅读成本，要么难以执行。对工程师，他建议别细读 LLM 文档，也别手写只为留痕的文档，把精力留给真正用于沟通的写作。

**「启示」** 作者的核心结论是，LLM 摧毁了写作作为合规、努力与学习证据的功能，组织却尚无好替代；因此在过渡期，写作应回归沟通，而不是继续充当可被轻易伪造的工作量证明。
